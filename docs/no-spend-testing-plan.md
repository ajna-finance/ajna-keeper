# No-Spend Coverage Plan: Aggregator System (SushiSwap + LI.FI), Hybrid Provider Selection, and Full Keeper Lifecycle

## Goal & current state

The no-spend story works in parts but not as a whole. What works fund-free today: the egress guard and Base-fork boot in `scripts/run-no-spend-validation.mjs`; the mock-EVM aggregator suites (`tests/integration/oneinch-aggregator-taker.test.ts`, `sushi-aggregator-taker.test.ts`, `helpers/mock-taker-base.ts`) that execute the REAL LI.FI/Sushi/1inch taker contracts against a deployed `MockLifiSwapTarget`; the hybrid-selection ranking unit tests (`tests/unit/hybrid-external-take-selection.test.ts`, `hybrid-external-take-probes.test.ts`); and the gated multi-provider fork loop (`tests/integration/hybrid-fork-loop.test.ts`). What is broken or gated: (1) the flagship `npm run no-spend-validation` FAILS because fixture creation times out on `eth_estimateGas` against a cold `latest`-pinned Base fork (`scripts/no-spend/runtime.mjs`; cold lazy-state cascade in `scripts/create-liquidatable-ajna-fixture-cli.ts` estimateGas calls); (2) only `LiquiditySource.UNISWAPV3` is executed end-to-end through the fixture harness — the aggregator takers and the hybrid "which provider" decision are never exercised against a real Ajna auction (`scripts/fixture-keeper-harness-cli.ts` hardcodes UNISWAPV3 at lines 310/399/516/719); (3) settlement is NOT asserted anywhere — the fixture harness never calls `handleSettlements`, and `daemon-smoke.mjs:467` hardcodes a `coveredCycles:['take','settlement']` label that is aspirational (its config has no settlement policy, so `shouldRunSettlementLoop` returns false and `runSettlementCycle` never runs); (4) the 1inch real-API leg is blocked by a 401 `ONEINCH_API_KEY`.

## Direct answer: yes, the whole system can be tested without funds

Yes. The combination of three already-present primitives makes a fully fund-free, egress-free proof of the entire system achievable:

- **A deployed on-chain mock aggregator target** (`contracts/mocks/MockLifiSwapTarget.sol::mockSwap`) lets the REAL LI.FI/Sushi/1inch taker contracts run a real `pool.take` → `atomicSwapCallback` → swap → exact-fill/ceiling backstop against the REAL fixture Ajna auction, with zero live-API egress. Provider identity is purely the registered `LiquiditySource` + normalized `providerId` — the same mock contract serves every provider, so the 401 1inch key is irrelevant when 1inch executes against the mock.
- **A localhost mock quote source** — either an HTTP server behind `config.lifi.apiBaseUrl` / `config.sushiAggregator.apiBaseUrl` (`src/dex/lifi/client.ts:230`, `src/dex/sushi-aggregator/client.ts:37`), or injected mock-backed providers in `createDiscoveryExternalTakeProviderRegistry` (`src/discovery/external-take/providers.ts:292`) — lets the REAL quote→validate→normalize→evaluate→approve→rank pipeline run with deterministic economics inside the egress guard.
- **The real hybrid decision engine** (`evaluateHybridExternalTakeForDiscovery`, `src/discovery/external-take/hybrid.ts:473`) then probes all providers, ranks them via `sortExternalTakeQuoteEvaluationsForSelection` (`selection.ts:51`), and selects a winner — so we assert WHICH provider wins, not just that a take happens.

What becomes possible once the packets below land: a single `npm run no-spend-validation` invocation that (a) builds a real kicked Ajna auction on a pinned warm fork, (b) makes LI.FI + Sushi + a mock-1inch all genuinely compete in the keeper's ranking with the expected winner selected and asserted, (c) executes the winning provider's REAL taker contract calldata-take against the real auction via the mock swap target, and (d) drives the auction to bad debt and asserts on-chain settlement (`auctionInfo.kickTime_ → 0`, bonds unlocked) — fund-free and egress-free. The truly-real-route proof (live li.quest/Sushi routes, 1inch when keyed) remains the gated `tests/integration/hybrid-fork-loop.test.ts`, promoted to a first-class script in P1.

## Work packets

### P0-1 — Make the flagship no-spend harness reliable (kill the fixture-creation estimateGas timeout)

- **Objective:** `npm run no-spend-validation` must reliably reach fixture creation and beyond; the current `eth_estimateGas` timeout against a cold `latest` fork blocks everything else.
- **Approach:** (a) Stop defaulting the fork to `latest`: change `DEFAULT_BASE_FORK_BLOCK` and the `options.baseForkBlock` resolution (`scripts/run-no-spend-validation.mjs:45,76-79`) to a pinned, known-warm block number; `resolveForkBlock` (`runtime.mjs:180-202`) and `hardhat.config.ts:55` (`BASE_FORK_BLOCK`) already honor an explicit number, and the replay command is only reproducible if the original run pinned. (b) Add retry/backoff around the unretried contract `estimateGas`/deploy calls in `create-liquidatable-ajna-fixture-cli.ts` (Uniswap seeding lines ~2175/2214; external-take deploy ~2484/2503/2511) — today only `evm_*` control calls are wrapped (`isRetryableLocalRpcError`/`sendLocalEvmControl` ~846/864). (c) Pre-warm the cold reads: issue the Ajna/Uniswap state reads once (untimed) before the budgeted estimateGas, and/or raise the ethers provider `pollingInterval`/timeout. Note `runtime.mjs` `DEFAULT_RPC_TIMEOUT_MS=120_000` only governs the chainId poll, not the fixture child — do not just bump that.
- **No-spend mechanism:** Pure reliability/determinism; no new spend or egress. Localhost fork only.
- **Tests/assertions:** Fixture creation completes within budget on the pinned block across 3 consecutive runs; `validationReport.resolvedForkBlockNumber/Hash` recorded and the emitted `replayCommand` re-runs deterministically; existing strict-hybrid asserts still pass unchanged.
- **Effort:** M. **Risk:** Med — picking a warm block that still has a kickable/liquidatable position for the fixture; mitigate by validating the chosen block produces a viable auction before pinning.
- **Dependencies:** None. Gates every other P0.

### P0-2 — Local mock aggregator target + mock quote source so LI.FI/Sushi/1inch EXECUTE real taker calldata-takes against the real fixture auction

- **Objective:** Deploy the aggregator takers on the fixture fork and execute a REAL calldata-take through each provider's taker contract against the REAL Ajna auction, with no live API.
- **Approach:** (a) Generalize fixture deploy from Uniswap-only to a descriptor loop: extend `deployExternalTakeContracts` (`create-liquidatable-ajna-fixture-cli.ts:2436-2529`) to also deploy `LifiKeeperTaker`, `SushiAggregatorKeeperTaker`, `OneInchAggregatorKeeperTaker` (+ a `MockLifiSwapTarget`), mirroring `tests/integration/helpers/mock-taker-base.ts::deployAggregatorTaker` (179-217) and the canonical multi-taker deploy in `hybrid-fork-loop.test.ts::deployHybridFactorySystem` (226-268). Register each via `TakerRouter.setTaker(LiquiditySource.X, taker)` — Sushi MUST use `SUSHI_AGGREGATOR(6)`, never the rejected legacy `SUSHISWAP(3)` (`TakerRouter.sol:64-66`). Allowlist the mock on each taker via `setCallTarget`/`setApprovalSpender`/`setCallSelector` (`BaseAggregatorCalldataTaker.sol:168-196`). (b) Add a sibling `FixtureSummary` field (e.g. `aggregatorTakers[]` of `{source, takerAddress, targetAddress}`) alongside `uniswapV3ExternalTake` (`~line 285/90-94`) so the harness can read them. (c) Supply the quote: stand up a localhost mock HTTP server returning LI.FI/Sushi-shaped quotes whose `transactionRequest.to` = the deployed `MockLifiSwapTarget` and `.data` = encoded `mockSwap(collateral, quote, taker, amountIn, amountOut)`, and point `dex.lifi.apiBaseUrl`/`dex.sushiAggregator.apiBaseUrl` at it (SEAM B); OR, if avoiding HTTP, add a test-only injection so `requestValidatedLifiQuote`/`requestValidatedSushiQuote` return a built `ApprovedCalldataAggregatorQuote` (SEAM/function seam). 1inch MUST use the mock-URL/registry path (its live key is 401).
- **No-spend mechanism:** REAL taker contract runs `pool.take` → `atomicSwapCallback` → `_executeAggregatorCall` → `mockSwap` (consumes approved collateral, pays pre-minted quote) on localhost; no li.quest/1inch/Sushi egress.
- **Critical invariants to respect:** `amountInTokenUnits` MUST equal the pool's debt-constrained callback collateral (`BaseAggregatorCalldataTaker.sol:279` `UnexpectedSourceBalance`) — derive `amountIn` from the LIVE auction at execution time, never hardcode. The mock's `amountOut` MUST clear `max(approvedMinOutRaw, quoteAmountDueCeiling)` (+1 token-wei when `quoteTokenScale>1`) or it fails `InsufficientQuoteReceived`. The mock address must be in BOTH the off-chain config allowlists (`validateLifiQuote`, `validate-route.ts:118-230`) AND on-chain taker storage (fail-closed both layers; `swapRouter.code.length>0`). `providerId` must match the source (`quote-evaluation.ts:161-171`). Pre-mint the pool's quote token to the mock target as payout reserve.
- **Real-Ajna-vs-mock divergence:** The swap TARGET is a mock but the Ajna pool/auction/callback are REAL — assert on keeper decision + collateral-reduced + approvals-reset, NOT on exact swap-output economics the mock can't faithfully reproduce (per `ajna-take-callback-semantics` / `calldata-aggregator-exact-fill-invariant`).
- **Tests/assertions:** For each of LI.FI / Sushi / mock-1inch run individually: take executes; auction collateral strictly reduced; taker token approvals reset to 0; donated-dust immunity (optionally exercise `MockLifiSwapTarget` refund/no-output/wrong-token variants to fire `UnexpectedSourceBalance`/`InsufficientQuoteReceived`/`nonReentrant` backstops). Egress artifact clean.
- **Effort:** L. **Risk:** Med-High — exact-fill/ceiling sizing against the live auction is the load-bearing detail. **Dependencies:** P0-1.

### P0-4 — Add an explicit SETTLEMENT assertion to the lifecycle

- **Objective:** Stop asserting a settlement LABEL and start asserting settlement BEHAVIOR (bad debt cleared on-chain).
- **Approach:** Primary seam — add a settlement stage to the fixture harness: after the take loop completes (`fixture-keeper-harness-cli.ts`, after ~line 764, before reading `keeperQuoteBalanceAfter`), call `handleSettlements` (`src/settlement/index.ts:196`) with `poolConfig.settlement:{enabled:true, minAuctionAge:0, maxBucketDepth:50, maxIterations:10}` and a fixture subgraph reader (the stub at `scripts/no-spend/fixture-subgraph.ts` already serves `liquidationAuctions`). Set `minAuctionAge:0` because `isAuctionOldEnough` (`checks.ts:56-62`) compares `Date.now()-kickTime` and the fork's warped chain time diverges from wall-clock. The fixture's `keeper` wallet is the kicker, so `checkBotIncentive` passes either way. Alternate/complementary seam — make `daemon-smoke.mjs` honest: add a discovery/manual settlement policy to `buildDaemonConfig` (~142-213) so `shouldRunSettlementLoop` returns true and `runSettlementCycle` actually runs (`auto-discover-validation.ts:668` requires `defaults.settlement` when `discovery.settlement` is enabled), then replace the hardcoded `coveredCycles:['take','settlement']` label (`:467`) with a real `settlementExecuted` invariant.
- **No-spend mechanism:** Pure on-chain Ajna `settle()` — touches NO aggregator, so the 401 1inch key and LI.FI gating are irrelevant. Must run with `dryRun:false` (the dry-run branch short-circuits without tx, `execution.ts:18-28`).
- **Bad-debt precondition (must be manufactured and asserted):** `needsSettlement` returns true ONLY when `collateral.eq(0) && debt.gt(0)` (`checks.ts:108`). A single take leaves residual collateral, so the harness's auto-warp+re-take loop (`:691-764`) must drive the auction to ZERO collateral with residual debt FIRST. The test must ASSERT this precondition was reached, else `findSettleableAuctions` finds nothing and the test silently passes proving nothing.
- **Tests/assertions:** Before: `liquidationStatus.collateral==0 && debt>0`. After settle: `pool.contract.auctionInfo(borrower).kickTime_` transitions non-zero → 0 (the exact terminal predicate `execution.ts:42-52`); `pool.kickerInfo(signerAddress).locked → 0` (bonds unlocked). Dry-run parity leg: run settlement once with `dryRun:true` and assert ZERO `settle()` txs (reuse `countTransactionsFrom`/`evm_snapshot`/`evm_revert` from `daemon-smoke.mjs:239-260/393/413`), then `dryRun:false` and assert ≥1. Call `clearSharedSettlementScannerCache()` (`scanner.ts:35`) between assertions; run settlement AFTER all take reads or inside its own snapshot (settle is irreversible).
- **Effort:** M. **Risk:** Med — reaching zero-collateral-with-debt deterministically; `minAuctionAge`/kickTime unit pitfalls. **Dependencies:** P0-1 (independent of aggregator packets — closeable in parallel).

## Recommended execution order & definition of done

**Order:** P0-1 (unblocks everything) → P0-2 (provider execution) → P0-4 (settlement; can run parallel to P0-2 since it's aggregator-independent) → P0-3 (hybrid decision) → P1-1 (compose full lifecycle) → P1-2 (real-route first-class) → P2-1 (realism/canaries).

**Definition of done — the commands that prove the system fund-free:**

1. `npm run no-spend-validation` (pinned warm `BASE_FORK_BLOCK`, hybrid/aggregator scenario via the forwarded `AJNA_AGENT_HARNESS_*` env + `ROUTE_SELECTION_MODE=maximize_profit`) completes green and its single JSON report asserts, in one run: real kicked Ajna auction (kick) → all providers (LI.FI + Sushi + mock-1inch) probed and ranked with the **expected winner selected** (`routeArtifact.selectedLiquiditySource` = the intended provider, NOT hardcoded UNISWAPV3) → the **winning provider's real taker contract** executed a calldata-take against the real auction via the mock swap target (collateral reduced, approvals reset) → the auction driven to bad debt and **settlement asserted on-chain** (`auctionInfo.kickTime_ → 0`, bonds unlocked) → egress artifact clean (no non-allowlisted host) + secret-scrub artifact clean + dry-run/execution tx-count parity.
2. The gated real-route complement runs fund-free on demand: `RUN_HYBRID_FORK_LOOP=1 AJNA_AGENT_HYBRID_FORK_CONFIG=<reviewed> npm run test:hybrid-fork-loop` (dry-run default) plus `npm run verify:routes` for live LI.FI/Sushi/Curve route health (1inch skip-on-401).

Together these prove selection + every provider's execution + the full kick→discover→quote→select→take→settle lifecycle without spending real funds, while respecting the fail-closed allowlists (both off-chain and on-chain), the exact-fill/ceiling invariants, the subsidy-vs-profit ranking rules, and the real-Ajna-vs-mock-swap divergence boundary (assert keeper decision + on-chain auction/settlement state, not mock swap economics).
