# No-Spend Coverage Plan: Aggregator System (SushiSwap + LI.FI), Hybrid Provider Selection, and Full Keeper Lifecycle

## Goal & current state

The no-spend story works in parts but not as a whole. What works fund-free today: the egress guard and Base-fork boot in `scripts/run-no-spend-validation.mjs`; the mock-EVM aggregator suites (`tests/integration/oneinch-aggregator-taker.test.ts`, `sushi-aggregator-taker.test.ts`, `helpers/mock-taker-base.ts`) that execute the REAL LI.FI/Sushi/1inch taker contracts against a deployed `MockLifiSwapTarget`; the hybrid-selection ranking unit tests (`tests/unit/hybrid-external-take-selection.test.ts`, `hybrid-external-take-probes.test.ts`); and the gated multi-provider fork loop (`tests/integration/hybrid-fork-loop.test.ts`). What is broken or gated: (1) the flagship `npm run no-spend-validation` FAILS because fixture creation times out on `eth_estimateGas` against a cold `latest`-pinned Base fork (`scripts/no-spend/runtime.mjs`; cold lazy-state cascade in `scripts/create-liquidatable-ajna-fixture-cli.ts` estimateGas calls); (2) only `LiquiditySource.UNISWAPV3` is executed end-to-end through the fixture harness — the aggregator takers and the hybrid "which provider" decision are never exercised against a real Ajna auction (`scripts/fixture-keeper-harness-cli.ts` hardcodes UNISWAPV3 at lines 310/399/516/719); (3) settlement is NOT asserted anywhere — the fixture harness never calls `handleSettlements`, and `daemon-smoke.mjs:467` hardcodes a `coveredCycles:['take','settlement']` label that is aspirational (its config has no settlement policy, so `shouldRunSettlementLoop` returns false and `runSettlementCycle` never runs); (4) the 1inch real-API leg is blocked by a 401 `ONEINCH_API_KEY`.

## Direct answer: yes, the whole system can be tested without funds

Yes. The combination of three already-present primitives makes a fully fund-free, egress-free proof of the entire system achievable:

- **A deployed on-chain mock aggregator target** (`contracts/mocks/MockLifiSwapTarget.sol::mockSwap`) lets the REAL LI.FI/Sushi/1inch taker contracts run a real `pool.take` → `atomicSwapCallback` → swap → exact-fill/ceiling backstop against the REAL fixture Ajna auction, with zero live-API egress. **On-chain, one mock target serves every taker** because the takers gate calls by allowlist (`setCallTarget`/`setCallSelector`), not by aggregator ABI — so the 401 1inch key is irrelevant once 1inch's taker executes against the allowlisted mock. **The off-chain quote pipeline is the asymmetry (see next bullet):** only LI.FI's validator treats calldata opaquely; Sushi and 1inch fail-close on a generic `mockSwap`.
- **A localhost mock quote source**, with a provider-specific feasibility split the implementer MUST respect — a single generic `mockSwap`+HTTP path does NOT serve all three off-chain validators:
  - **LI.FI** — a mock server behind `config.lifi.apiBaseUrl` (`src/dex/lifi/client.ts:230`) returning a `mockSwap`-shaped quote DOES pass the real validate→normalize pipeline: LI.FI's validator is opaque (selector + target allowlist only, `src/dex/lifi/validate-route.ts:225-234`). Caveat: executing a take forces `mode:'production'`, which forces HTTPS, so the mock server must be HTTPS — see P0-2; the injection seam (last bullet) sidesteps this.
  - **Sushi** — the HTTP server behind `config.sushiAggregator.apiBaseUrl` (`src/dex/sushi-aggregator/client.ts:37`) is NOT sufficient: `validate-route.ts:27-29,149-189` fail-closes any selector other than the proven `0x5f3bd1c8` and parses a fixed 5-head-word layout `[tokenIn, amountIn, recipient, tokenOut, amountOutMin]`. A generic `mockSwap` (`0x79c6257b`) is rejected before normalize. No-spend Sushi requires EITHER a provider-shaped mock (a target emitting `0x5f3bd1c8` with that head layout) OR the registry-injection seam (last bullet).
  - **1inch** — there is no `apiBaseUrl`/mock-URL seam for the no-spend path at all: `convertSwapApiResponseToDetails` → `decodeSwapCalldata` decodes against the GenericRouter ABI and pins `tx.to` to the configured router (`src/take/oneinch-aggregator/quote-service.ts:135-153`, `src/dex/one-inch.ts:34-37`), so a `mockSwap`-shaped response is rejected before any take. The ONLY feasible no-spend 1inch seam is the registry/function injection below.
  - **Registry-injection seam (covers all three; required for Sushi/1inch):** inject mock-backed providers in `createDiscoveryExternalTakeProviderRegistry` (`src/discovery/external-take/providers.ts:292`) / the per-provider `requestValidated*Quote` callbacks — `requestValidatedLifiQuote` (`src/take/lifi/quote-service.ts:47`), `requestValidatedSushiAggregatorQuote` (`src/take/sushi-aggregator/quote-service.ts:64`), `requestValidatedOneInchAggregatorQuote` (`src/take/oneinch-aggregator/quote-service.ts:93`) — returning a built quote whose `transactionTarget`=the allowlisted mock (Sushi/1inch return `ApprovedCalldataAggregatorQuote`; LI.FI's `requestValidatedLifiQuote` returns `ApprovedLifiQuote`, so inject the LI.FI-shaped object there — see P0-2). This bypasses the provider-specific calldata validators while still exercising the REAL evaluate→approve→rank pipeline.

  NOTE: the existing mock-aggregator taker suites pass only because they hand-encode `getSighash('mockSwap')` calldata straight to the on-chain taker (`tests/integration/sushi-aggregator-taker.test.ts:120`), bypassing the off-chain validators — they do NOT prove the generic quote path works for Sushi/1inch.
- **The real hybrid decision engine** (`evaluateHybridExternalTakeForDiscovery`, `src/discovery/external-take/hybrid.ts:473`) then probes all providers, ranks them via `sortExternalTakeQuoteEvaluationsForSelection` (`selection.ts:51`), and selects a winner — so we assert WHICH provider wins, not just that a take happens.

What becomes possible once the packets below land: a single `npm run no-spend-validation` invocation that (a) builds a real kicked Ajna auction on a pinned warm fork, (b) makes LI.FI + Sushi + a mock-1inch all genuinely compete in the keeper's ranking with the expected winner selected and asserted, (c) executes the winning provider's REAL taker contract calldata-take against the real auction via the mock swap target, and (d) drives the auction to bad debt and asserts on-chain settlement (`auctionInfo.kickTime_ → 0`, bonds unlocked) — fund-free and egress-free. The truly-real-route proof (live li.quest/Sushi routes, 1inch when keyed) remains the gated `tests/integration/hybrid-fork-loop.test.ts`, promoted to a first-class script in P1.

### P0-1 — Make the flagship no-spend harness reliable (kill the fixture-creation estimateGas timeout)

- **Objective:** `npm run no-spend-validation` must reliably reach fixture creation and beyond; the current `eth_estimateGas` timeout against a cold `latest` fork blocks everything else.
- **Approach:** (a) Stop defaulting the fork to `latest`: change `DEFAULT_BASE_FORK_BLOCK` and the `options.baseForkBlock` resolution (`scripts/run-no-spend-validation.mjs:45,76-79`) to a pinned, known-warm block number; `resolveForkBlock` (`runtime.mjs:180-202`) and `hardhat.config.ts:55` (`BASE_FORK_BLOCK`) already honor an explicit number. The motivation is the cold-tip cascade: a freshly-resolved `latest` tip block has no warm upstream state cache, so the first `estimateGas` triggers the slow lazy-state fetch; pinning to a known-warm block avoids it. (Replay reproducibility is NOT the reason — `buildReplayCommand` already substitutes the RESOLVED concrete block number, `report-artifacts.mjs:7-8`, so past runs replay deterministically regardless.) (b) Add retry/backoff around the unretried contract `estimateGas`/deploy calls in `create-liquidatable-ajna-fixture-cli.ts` (Uniswap seeding lines ~2175/2214; external-take deploy ~2484/2503/2511) — today only `evm_*` control calls are wrapped (`isRetryableLocalRpcError`/`sendLocalEvmControl` ~846/864). **But scope the expectation:** retry only guards TRANSIENT RPC *errors* (`isRetryableLocalRpcError` matches `SERVER_ERROR`/`ECONNRESET`/`ECONNREFUSED`/`ETIMEDOUT`/'missing response'/'socket hang up', `:852-861`); it does NOT rescue a slow/hung cold `estimateGas`, which never errors — that failure mode is fixed by (a) pinning + (c) pre-warming, not by retry. **A hard timeout is REQUIRED, not optional** — the harness spawns the fixture via `runNodeScript` (`run-no-spend-validation.mjs:736-753`), which has NO timeout and resolves only on child `close` (`runtime.mjs:329-357`), unlike `runLoggedCommand` which honors `timeoutMs` + SIGTERM/SIGKILL (`runtime.mjs:272-283`). So a cold hang blocks indefinitely and the "completes within budget" assertion is unenforced. Give the fixture spawn a budgeted `timeoutMs` (mirror `runLoggedCommand`'s SIGTERM/SIGKILL), AND/OR set the fixture provider's `connection.timeout` / wrap `estimateGas` in `Promise.race`, and define the concrete budget the assertion checks. (c) Pre-warm the cold reads: issue the Ajna/Uniswap state reads once (untimed) before the budgeted estimateGas, and/or raise the ethers provider `pollingInterval`/timeout. Note `DEFAULT_RPC_TIMEOUT_MS=120_000` (defined in `run-no-spend-validation.mjs:44`, consumed in `waitForRpcReady`/`run-no-spend-validation.mjs:247`) only governs the `eth_chainId` readiness poll, not the fixture child — do not just bump that.
- **No-spend mechanism:** Pure reliability/determinism; no new spend or egress. Localhost fork only.
- **Tests/assertions:** Fixture creation completes within budget on the pinned block across 3 consecutive runs; `validationReport.resolvedForkBlockNumber/Hash` recorded and the emitted `replayCommand` re-runs deterministically; existing strict-hybrid asserts still pass unchanged.
- **Effort:** M. **Risk:** Med — the fixture is fully SYNTHETIC (it deploys its own mock ERC20s, creates its OWN Ajna ERC20 pool via the real factory, seeds Uniswap, and kicks its own borrower — `create-liquidatable-ajna-fixture-cli.ts:789,1074-1105`), so the pinned block does NOT need a pre-existing on-chain liquidatable borrower. The real dependency is a block where the Ajna `ERC20PoolFactory` + Uniswap V3 contracts are deployed and Uniswap liquidity seeding is viable. Mitigate by running fixture creation once end-to-end (deploy tokens → create pool → seed Uniswap → kick) on the candidate block before pinning.
- **Dependencies:** None. Gates every other P0.

### P0-4 — Add an explicit SETTLEMENT assertion to the lifecycle

## Recommended execution order & definition of done

**Order:** P0-1 (unblocks everything) → P0-2 (provider execution + negative-take) → P0-4 (settlement incl. multi-iteration/partial; parallel to P0-2 since it's aggregator-independent) → P0-3 (hybrid decision) → P0-5 (reward-swap money-safety) → P1-1 (compose full lifecycle + partial-fill + mixed-availability) → P1-2 (real-route first-class) → P1-3 (daemon resilience) → P2-1 (token/multi-auction realism) → P2-2 (price + multi-chain). **Parallelizable from the start** (need only P0-1's fixture, or no fork at all): P0-5, P1-3, and the P2-2 config matrix — these maximize surface area independently of the aggregator critical path.

**Definition of done — the commands that prove the system fund-free:**

1. `npm run no-spend-validation` (pinned warm `BASE_FORK_BLOCK`, hybrid/aggregator scenario via the forwarded `AJNA_AGENT_HARNESS_*` env + `AJNA_AGENT_HARNESS_ROUTE_SELECTION_MODE=maximize_profit`) completes green and its single JSON report asserts, in one run: real kicked Ajna auction (kick) → all providers (LI.FI + Sushi + mock-1inch) probed and ranked (asserted over `routeArtifact.probedProviders`, the roster added in P0-3) with the **expected winner selected** (`routeArtifact.selectedLiquiditySource` = the intended provider, NOT hardcoded UNISWAPV3) → the **winning provider's real taker contract** executed a calldata-take against the real auction via the mock swap target (collateral reduced, approvals reset) → the auction driven to bad debt and **settlement asserted on-chain** (`auctionInfo.kickTime_ → 0`, bonds unlocked) → egress artifact clean (no non-allowlisted host) + secret-scrub artifact clean + dry-run-broadcasts-nothing and snapshot/revert state-integrity (`buildStateIntegrityArtifact`). (Full `countTransactionsFrom` dry-run-vs-execution tx-count parity currently lives only in `daemon-smoke.mjs:239,407,446`; port it into the `no-spend-validation` execution leg if true count parity is wanted in the flagship run.)
2. The gated real-route complement runs fund-free on demand: `AJNA_AGENT_HYBRID_FORK_CONFIG=<reviewed> npm run hybrid-fork-loop` (dry-run default) — use the EXISTING `hybrid-fork-loop` script, which already exports `RUN_HYBRID_FORK_LOOP=true HARDHAT_CHAIN_ID=8453 FORK_NETWORK=base` internally. Plus `npm run verify:routes` for live LI.FI/Sushi/Curve route health (1inch skip-on-401).
3. **Surface-area / assurance breadth (beyond the flagship happy path).** The plan maximizes tested surface by ALSO asserting the keeper's FAILURE and non-happy-path behavior fund-free: a take that reverts on-chain is handled without crashing and is classified pre/post-broadcast (P0-2 negative-take); the settlement loop genuinely iterates and resumes after a partial clear (P0-4); the reward-token swap honors operator slippage and fails closed rather than taking a near-total loss (P0-5); the long-running daemon loops, recover from a transient failure, skip on a gas spike, and fail over read-RPCs (P1-3); a debt-constrained partial fill and a provider that returns no route are ranked correctly (P1-1); and the price/oracle path + 6-chain config wiring are exercised (P2-2). Together these prove selection + every provider's execution + the full kick→discover→quote→select→take→settle lifecycle — PLUS the keeper's failure handling, money-safety (take ceiling/backstops AND reward-swap min-out), daemon resilience, settlement-loop completeness, and price/multi-chain inputs — without spending real funds, while respecting the fail-closed allowlists (both off-chain and on-chain), the exact-fill/ceiling invariants, the subsidy-vs-profit ranking rules, and the real-Ajna-vs-mock-swap divergence boundary (assert keeper decision + on-chain auction/settlement state, not mock swap economics).
